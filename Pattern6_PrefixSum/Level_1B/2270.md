The confusing part is why we use i < nums.length - 1 instead of i < nums.length.

Let's forget the code for a moment.

What does "split" mean?

Suppose:

nums = [10, 4, -8, 7]

We need to divide the array into two parts:

LEFT | RIGHT

Both parts must contain at least one element.

Split at index 0
[10] | [4, -8, 7]

✅ Valid

Split at index 1
[10, 4] | [-8, 7]

✅ Valid

Split at index 2
[10, 4, -8] | [7]

✅ Valid

Split at index 3
[10, 4, -8, 7] | []

❌ Not valid

There is nothing on the right.




why used long instead of int

Because prefix sum can become too large for int.

1. int has a limit

Java int can store:

-2,147,483,648  to  2,147,483,647

So the maximum positive int is about 2.1 billion.

2. Prefix sum adds many numbers

Suppose:

nums = [1,000,000,000, 1,000,000,000, 1,000,000,000]

Prefix sums become:

1,000,000,000
2,000,000,000
3,000,000,000  ← too big for int

3,000,000,000 cannot fit inside an int.

So we use:

long
3. long has a much bigger range

Java long can store approximately:

-9,223,372,036,854,775,808
to
 9,223,372,036,854,775,807

So it can easily store the large prefix sums.
